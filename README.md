# Analysis Lab: IB Mathematics: Analysis and Approaches HL (May 2028)

An interactive study guide to **IB Mathematics: Analysis and Approaches (AA)** at **Standard Level (SL)** and **Higher Level (HL)** for the **May 2028 examination** (First Assessment 2021 syllabus, final assessment November 2028):

- **Topic 1.** Number and algebra (`1.1` to `1.5` — SL 1.1–1.9 & AHL 1.10–1.16)
- **Topic 2.** Functions (`2.1` to `2.3` — SL 2.1–2.11 & AHL 2.12–2.16)
- **Topic 3.** Geometry and trigonometry (`3.1` to `3.3` — SL 3.1–3.8 & AHL 3.9–3.18)
- **Topic 4.** Statistics and probability (`4.1` and `4.2` — SL 4.1–4.12 & AHL 4.13–4.14)
- **Topic 5.** Calculus (`5.1` to `5.4` — SL 5.1–5.11 & AHL 5.12–5.19)

There are 17 topic pages (`t1-1` to `t1-5`, `t2-1` to `t2-3`, `t3-1` to `t3-3`, `t4-1` to `t4-2`, and `t5-1` to `t5-4`), a home page (`index.html`), and a mixed practice arena (`practice.html`).

It is written for students who already know basic algebra mechanics from Year 10, but want to master **decoding IB exam questions**, **practical modelling**, and **multi-step problem solving**. Every topic page includes:
- Plain-English **Question Decoders** (*"When an exam question says …, here is what it actually asks you to set up"*),
- Interactive visual models (2D function/calculus/distribution plotters and rotatable 3D vector/plane/volume viewers),
- Step-by-step worked examples you reveal one line at a time, with explicit *"Why this step"* notes and IB markscheme tags (`M1`, `A1`, `R1`),
- "Try it" calculations that accept decimals to 3 significant figures, scientific notation, fractions (`3/4`), or exact expressions (`pi/3`, `sqrt(3)/2`),
- Explicit **Not needed for IB** (`callout--scope`) boundaries so students using AI tutors do not waste time on out-of-syllabus university techniques,
- Original practice questions across Foundation, Exam style (Paper 1 No-GDC, Paper 2 GDC), and Challenge (multi-topic synthesis and HL Paper 3 style) tiers.

The site can be read in **English** (`en`), **Traditional Chinese — Hong Kong curriculum terms** (`zh-Hant`), **Japanese** (`ja`), or **Korean** (`ko`). You choose the language manually in the header: the site always starts in English and never switches by itself, and key terms, exam tips, command terms, and the markscheme points and model answers of quiz questions stay visible in English alongside the translation. Worked examples, hints and solutions are translated (their mark codes such as `M1` and `A1` stay as they are).

This is an **unofficial** study aid. It is not produced, checked, or endorsed by the International Baccalaureate Organization (see the [disclaimer](#disclaimer)).

## How to run it

There is nothing to install or build.

- **On your computer:** download or clone the repository and open `index.html` in a browser. It works straight from `file://`. If you prefer a local server, run `python3 -m http.server 8000` in the repository folder and open `http://localhost:8000/`.
- **On GitHub Pages:** in the repository settings, open **Pages** and set **Source** to **GitHub Actions**. The workflow [`.github/workflows/pages.yml`](.github/workflows/pages.yml) then publishes the site on every push to `main` (or when you run it by hand from the Actions tab). It uploads only the files the site needs: `index.html`, `practice.html`, `LICENSE`, `topics/`, `assets/`, `data/` and `i18n/`. All links are relative, so the site works under any subpath (`https://<user>.github.io/<repository>/`).
- The empty `.nojekyll` file is only needed if you set the Pages source to "Deploy from a branch" instead: it tells Pages to serve the files as they are. The workflow adds one to the published folder too.

The site is plain HTML, CSS and JavaScript. Its only external requests are to Google Fonts, and it falls back to system fonts if that is unavailable. There is no tracking, no account and no server. Progress is saved in your own browser (`localStorage`) and never leaves it.

## Contributing

Corrections are very welcome, especially to the mathematics and markscheme steps.

1. Read [`docs/AUTHORING.md`](docs/AUTHORING.md). It defines the page skeleton, every component's markup, the question schema and the style rules. For translations, read [`docs/TRANSLATING.md`](docs/TRANSLATING.md).
2. Keep it static: no build tools, no frameworks, no external scripts.
3. Check your change from `file://`, in light and dark themes, at phone width, with the browser console open.
4. Questions must be your own work. Do not submit copyrighted IB past-paper questions or close paraphrases.

### Contributing a translation

Translations are overlay files: nobody edits the English pages, and a missing translation simply shows the English. To improve Japanese, Traditional Chinese or Korean, edit the value (never the key) in `i18n/<lang>/<page>.js` or `i18n/<lang>/<page>.q.js`, following the glossary in `docs/`, then run

```
node tools/i18n-check.js zh-Hant       # or ja, ko; add a page id such as t1-1 to check one page
```

until it ends with "All translated, nothing stale, all lints pass", and look at the page at desktop and phone width. The full workflow is in [`docs/TRANSLATING.md`](docs/TRANSLATING.md). The tools need Node.js and Playwright; the site itself needs neither.
