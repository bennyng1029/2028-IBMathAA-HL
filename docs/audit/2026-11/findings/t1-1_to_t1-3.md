## t1-1 Sequences, series and financial models

Checked: 17 questions, 2 worked examples, 2 Try-its, 2 widgets. All answers, distractors and widget calculations are correct except the items below.

### Critical

**C1. t1-1-q014 has no solution; the answer key relies on a false factorisation.** `data/questions-t1-1.js:229-242`
> "An arithmetic sequence has first term u_1 = 4 and common difference d = 3 … the 7th term of the geometric sequence [v_1 = 2, r = 2]" … "3n² + 5n − 256 = 0 ⇒ (3n + 32)(n − 8) = 0 ⇒ n = 8"

- (3n + 32)(n − 8) = 3n² **+ 8n** − 256, not 3n² + 5n − 256.
- The real roots of 3n² + 5n − 256 = 0 are n = (−5 ± √3097)/6 ≈ 8.44 and −10.1. Neither is an integer.
- Check: S₈ = 4(29) = 116 and S₉ = 144. No value of n gives S_n = 128.
- The markscheme (M1 "Factors as (3n + 32)(n − 8)", A1 "n = 8") and the solution repeat the error.

Fix: change the arithmetic sequence to u₁ = 9, d = 2. Then:
- S_n = (n/2)(18 + 2(n − 1)) = n(n + 8) = 128
- n² + 8n − 128 = 0 ⇒ (n + 16)(n − 8) = 0 ⇒ **n = 8**

Update the stem, answer, markscheme lines 233–236, hints and solution to match.

### Major

**M1. `S_infty` renders as "Sᵢnfty" and `^infty` renders as a literal "^∞".**
Affected lines:
- `topics/t1-1.html:41, 87, 88, 219, 230, 251, 254`
- `data/questions-t1-1.js:72, 77, 100, 186, 190, 223` (`S_infty`)
- `data/questions-t1-1.js:212, 277` (`Σ_{k=1}^infty`, `Σ_{n=1}^infty`)

What happens in `S1.math.formula`:
- `\binfty\b` does not match inside `S_infty`, because `_` is a word character.
- The `_i` is then turned into a subscript. Output: `S<sub>i</sub>nfty` (checked in node).
- In `^infty`, `infty` does become ∞, but the unbraced-superscript regex `[a-zA-Zθ]` does not accept ∞. Output: `Σ<sub>k=1</sub>^∞`.

This is the key sum-to-infinity notation, garbled in the checklist, the decoder, the Key-idea callout, the worked example and six questions.

Fix: write `S_{infty}` (renders S<sub>∞</sub>) and `^{infty}` (renders <sup>∞</sup>), or use `S_∞`. Both checked. The core fix is to add `∞` to the superscript character class and match `infty` without `\b`, but `math.js` is a core file.

**M2. Inflation is treated as "replace + with −".** `topics/t1-1.html:290`
> "For **annual depreciation** … or **inflation** adjustment, replace the plus sign with a minus sign: FV = PV × (1 - r / 100)^n."

- This is correct for depreciation.
- It is wrong for inflation. Prices grow by (1 + i/100)ⁿ, and the real value of an amount is FV/(1 + i/100)ⁿ.
- The usual IB treatment of real value runs the TVM solver or compound-interest formula with the rate (r − i)%.
- (1 − i/100)ⁿ is neither of these.

Suggested text: "For **annual depreciation** (an asset losing r% of its value each year), replace the plus sign with a minus sign: FV = PV × (1 − r/100)ⁿ. For **inflation**, prices grow by (1 + i/100)ⁿ; to find the real value of an investment, use the interest rate minus the inflation rate, (r − i)%, as the rate in the formula or the Finance Solver."

**M3. The self-marked short questions cannot reach full marks.**

- `t1-1-q017` (`:275`, marks 7): the markscheme has 6 points, so the best possible score is 6/7. "A2" is one point.
