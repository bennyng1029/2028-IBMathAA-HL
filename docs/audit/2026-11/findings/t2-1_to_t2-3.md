I worked through every worked example, Try-it, question answer, distractor, hint, solution and markscheme, and checked them with python3/sympy (roots, inverses, discriminants, ranges, GDC roots, 3 s.f.). ## t2-1 — Lines, functions, domains, inverses and composites (SL 2.1–2.5)

All of these are correct: the perpendicular-bisector example (3x − 2y + 7 = 0), the Try-it answers (7.5, 2, 1.5), the domain/range example, the inverse in the worked example (f⁻¹(x) = 3 − √(x + 2), x ≥ −2) and its solution x = (7 − √21)/2 ≈ 1.209, and all 18 question keys (q001–q018). The widget fixed points are also correct: (3 + √13)/2, 0, 3 and 3.

### Major

**M1. The worked example uses the "solve f(x) = x" shortcut on a decreasing function, which the page's own rule does not cover.**
- `topics/t2-1.html:91` and `:248` limit the shortcut correctly: *"(for increasing functions)"*, *"any intersection of an increasing function y = f(x) with y = f⁻¹(x) lies directly on the line y = x"*.
- But the worked example at `:259–283` has f(x) = (x − 3)² − 2 for **x ≤ 3**, which is **decreasing**. Step `:276` "Solve f(x) = x on the mirror line y = x" is then applied with no justification.
- For a decreasing function, f and f⁻¹ can also meet off the line y = x. For example, f(x) = −x³ meets its inverse at (1, −1).
- The answer happens to be right. Solving f(f(x)) = x gives x = 0.438, 1.209, 4.562 and 5.791; the 2-cycle {0.438, 4.562} is ruled out only because 4.562 > 3 lies outside Domain(f). A numeric scan of f − f⁻¹ on [−2, 3] finds only x ≈ 1.2087.
- The checklist at `:41` also states the shortcut with no condition.
- **Fix:** add an R1 line to step 3: "Since f is decreasing, intersections need not lie on y = x; check f(f(x)) = x: the other pair (x ≈ 0.438, f(x) ≈ 4.56) needs 4.56 ∈ Domain(f) = (−∞, 3], so it is rejected, and the only intersection is on y = x." Alternatively, change the example to an increasing branch. Change `:41` to "…by solving f(x) = x (valid when f is increasing)".

### Minor

**m1. `m_perp` renders as "m" + subscript "p" + "erp".** The formatter only subscripts one character when there are no braces. Affected: `topics/t2-1.html:125`, `:126` (×2), `:162`; `data/questions-t2-1.js:52`, `:54`. **Fix:** write `m_{perp}` (or `m_{⊥}`).

**m2. Midpoint formula is in the formula booklet.** `topics/t2-1.html:115` says *"You must memorize the parallel and perpendicular gradient relationships and the midpoint formula from Topic 3.1."* The AA booklet (SL 3.1) prints the midpoint formula; `assets/js/math.js:46` lists it too. **Fix:** "…memorize the parallel and perpendicular gradient relationships (the midpoint formula is in the booklet under SL 3.1)."

**m3. "By IB convention" overstates the rule, and the page contradicts itself.** `topics/t2-1.html:110` says *"(by IB convention, integers with a > 0)"*. The booklet sets no a > 0 convention, and the worked answer at `:155` itself accepts "−3x + 2y − 7 = 0". **Fix:** "(usually integers; any non-zero multiple is equivalent unless the question says otherwise)".

**m4. Midpoint coordinates are missing their brackets.** `topics/t2-1.html:143` shows `M = (−2+4)/2, (7+3)/2 = (1, 5)`. **Fix:** put the two fractions inside "( … , … )".

**m5. Misconception note explains the correct answer instead of the distractor.** `data/questions-t2-1.js:31` (q001, option 5x − 2y + 12 = 0) says *"You substituted (2, −1) with the wrong signs: 5(2) − 2(−1) = 12, so 5x − 2y = 12, giving 5x − 2y − 12 = 0."* **Fix:** "You moved the constant to the wrong side: 5x − 2y = 12 gives 5x − 2y − 12 = 0, not + 12. Check by substituting (2, −1): 10 + 2 + 12 ≠ 0."

**m6. Garbled misconception note.** `data/questions-t2-1.js:74` (q003, option x ≥ 5) says *"When dividing 10 ≥ 2x by −2, you forgot to reverse the inequality sign…"*. **Fix:** "From 10 − 2x ≥ 0 you get −2x ≥ −10; dividing by −2 reverses the sign, giving x ≤ 5, not x ≥ 5."

**m7. Self-inverse widget preset is misleading.**
- For the self-inverse model, f = f⁻¹ everywhere, so the button `assets/js/widgets-t2-1.js:103` *"Jump to f(x) = f⁻¹(x)"* has no specific target. It jumps to the fixed point x = 3 as if that were the only solution.
- Also, `:75` sets aMin = 1.5, where f(1.5) = 9 is off the y-range [−4, 5.5], so P is drawn off-chart.
- **Fix:** for `selfinv`, relabel the button "Jump to a fixed point on y = x" or hide it, and set aMin ≈ 2.

### Critical

**C1. q011: wrong answer key and unfinished hint/solution text.** `data/questions-t2-2.js:240–248`.
- Stem: solve ln(x + 2) = 4 − x to 3 s.f.
- Key: `answer: 2.79, tolerance: 0.015`.
- The true root is **x = 2.4967 → 2.50** (sympy nsolve; check: ln 4.4967 = 1.5033 and 4 − 2.4967 = 1.5033). A student who enters the correct 2.50 is marked wrong.
- Hint 2 (`:246`) is draft text: *"Check that ln(2.793 + 2) = ln(4.793) ≈ 1.567 and 4 − 2.793 = 1.207... Wait: let us check the exact intersection! … Let us use 2.50!"*
- The solution (`:248`) is a placeholder: *"Wait: let us update answer to 2.50 right now!"*
- **Fix:**
  - `answer: 2.50, tolerance: 0.005, sigfigs: 3`
  - Hint 2: "Use the intersect tool; you should find x ≈ 2.497."
  - Solution: "Graphing Y₁ = ln(x + 2) and Y₂ = 4 − x gives a single intersection at (2.4967, 1.5033), so x = 2.50 (3 s.f.)."

### Minor

**m1. GDC digits in the Try-it are wrong** (the final 1.40 is right). `topics/t2-2.html:318` says *"round x ≈ 1.39808"* and `:321` says *"(1.398, 4.047)"*. The true values are x = 1.39778 and y = e^x = 4.04621. **Fix:** "x ≈ 1.39778" and "(1.398, 4.046)".

**m2. Unsupported statistic.** `topics/t2-2.html:47` says *"More than half of Paper 1 quadratic questions never use the word 'discriminant'"*. **Fix:** "Many Paper 1 quadratic questions never use the word 'discriminant'…"

**m3. Overclaim about markschemes.** `topics/t2-2.html:205` says *"scores zero marks on every IB markscheme!"*. **Fix:** "usually loses the mark: markschemes expect an equation such as x = 2."

**m4. Definition misses the degenerate case.** `topics/t2-2.html:193` dfn says *"(ax + b)/(cx + d) with c ≠ 0, whose graph is a rectangular hyperbola…"*. You also need ad − bc ≠ 0: otherwise the function is constant with a hole and has no asymptotes. **Fix:** add "and ad − bc ≠ 0".

**m5. The rational-asymptote widget shows asymptotes for the degenerate case.** `assets/js/widgets-t2-2.js:119–133`. For example, a = 2, b = −2, c = 1, d = −1 (reachable from the default by moving b by one step) gives f ≡ 2. The widget still prints "VA x = 1", "HA y = 2" and "B = 0", and draws both asymptotes. **Fix:** when `a*d === b*c`, show "Degenerate: f(x) = a/c (constant, hole at x = −d/c); no asymptotes."

**m6. The discriminant-lab widget silently replaces a = 0 with 0.5.** `assets/js/widgets-t2-2.js:51` (`if (Math.abs(a) < 0.1) a = 0.5;`). The slider shows a = 0 while the readouts and graph use 0.5. **Fix:** set the slider min/step to skip 0 (e.g. options −2…−0.5, 0.5…2), or show "a ≠ 0 for a quadratic" when a = 0.

**m7. Syllabus tags.** q015 (`data/questions-t2-2.js:330`, exponential equation via u = 3ˣ) is tagged SL 2.7, and q017 (`:374`, log equation) is tagged SL 2.9. Solving exponential and log equations is SL 1.7 in the 2019 guide. Both are SL, so this only matters for filtering. **Fix:** tag "SL 1.7 / 2.7" and "SL 1.7".

**m8. Rendering:** `Delta`, `sqrt`, `x in R` show as literal words throughout this page. See X2.

The intro sentence at `:47` could also mention that most rows are HL.

**M2. Order question q003 accepts only one of several valid orders.** `data/questions-t2-3.js:65–72`.
- Stem: *"Arrange these transformations in a valid order…"* for y = −3f(2x − 8) + 1. Key: `[0, 1, 2, 3]`, i.e. horizontal stretch, horizontal translation, vertical stretch/reflection, vertical translation.
- Horizontal and vertical transformations are independent, so these orders are equally valid:
  - [2, 3, 0, 1]
  - [0, 2, 1, 3]
  - [2, 0, 3, 1]
  - [0, 2, 3, 1]
  - [2, 0, 1, 3]
- Each stretch only has to come before the translation in the same direction. The grader (`assets/js/quiz.js:270`) scores by exact position, so correct answers are marked wrong.
- **Fix:** reword the stem to "Arrange in the order: all horizontal transformations first, then vertical, with stretches before translations in each direction", or reduce it to one direction (e.g. only the two horizontal steps plus two distractors).

## Cross-cutting (affects all three pages; the cause is shared shell code outside these files)

**X1 (Minor).** Multi-letter unbraced subscripts. These are fixable in the topic files; occurrences are listed in t2-1 m1 and t2-3 m1. `S1.math.formula` only subscripts one character after `_` when there are no braces.

**X2 (Minor, for the shell owner).** `docs/AUTHORING.md:202` says `.chem` converts `alpha`, `beta`, `gamma`, `Delta`, `inf`, `sqrt(x)` and so on. `assets/js/math.js:101–131` only converts `pi`, `infty` and the comparison/arrow operators. I checked with node: `alpha^2 + beta^2` → "alpha² + beta²", `Delta = b^2 - 4ac` → "Delta = b² − 4ac", `sqrt(x + 2)` → "sqrt(x + 2)". Likewise `x in R`, `sum_{r=0}^n` and `subset` (t2-1 q011 solution) render as plain words. So on these pages students see "Delta", "alpha beta gamma" and "sqrt(…)" written out. Either implement the documented conversions in `math.js`, or switch the topic files to Unicode (Δ, α, √, ∈, ℝ, ⊆, Σ).
