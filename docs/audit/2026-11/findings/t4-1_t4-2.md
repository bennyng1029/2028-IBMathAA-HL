### Major

1. **The worked example calls r = 0.849 "strong", but the page's own scale says strong starts at 0.85.**
   - Where: `topics/t4-1.html:328` (also `:331`), against `:282`.
   - Line 282: "`0.85 ≤ |r| ≤ 1</span> (strong), <span class="chem">0.5 ≤ |r| &lt; 0.85</span> (moderate)`".
   - Line 328: "Reliable because *r* ≈ 0.849 indicates strong positive correlation".
   - The problem: √0.72 = 0.8485 < 0.85. By the page's own guide this is *moderate*, so the R1 reasoning contradicts the page.
   - Fix (either one):
     - Change the guide on line 282 to "`|r| ≥ 0.8`" for strong (and "`0.5 ≤ |r| < 0.8`" for moderate).
     - Or change the example so the product of gradients is above 0.7225, for example `x = 0.65y + 0.5`, and recompute.

2. **The regression widget draws lines that are not the least-squares lines of the plotted points.**
   - Where: `assets/js/widgets-t4-1.js:259-262` and `:297-302`.
   - The code comment says: "Two orthogonal zero-mean, unit-variance 10-vectors (sum = 0, sum of squares = 10, dot product = 0) … with exact mean (5, 6), SDs (2.0, 2.4), and correlation r".
   - The problem: the actual values are ΣU² = 9.0, ΣV² = 8.62 and U·V = −0.49. So the scatter's real SDs are 1.90 and about 2.19, not 2.0 and 2.4, and its real r is not the slider value.
   - The drawn lines use the theoretical a = 1.2r and c = r/1.2, not the plotted data. Examples of the mismatch:

     | Slider r | Scatter's real r | Real y-on-x slope | Drawn slope |
     |---|---|---|---|
     | 0.1 | 0.047 | 0.055 | 0.12 |
     | 0.7 | 0.688 | 0.793 | 0.84 |
     | 0 | −0.056 | — | — |

     At slider r = 0 the "perpendicular" lines are drawn for a scatter whose real r is −0.056.
   - This undermines what the widget is meant to show: that each line is the least-squares fit for its direction.
   - Fix (either one):
     - Use exactly orthonormal vectors. Take U = linspace standardised to population SD 1. Then take V = some vector minus its projection onto U and onto 1, standardised to population SD 1.
     - Or compute a, b, c and d from `pts` with population formulas.

3. **The ordering question has more than one defensible order.**
   - Where: `data/questions-t4-1.js:258-265` (q012).
   - The answer key is `[0, 1, 2, 3]`: plot and find r → check x₀ is inside the data range → find the y-on-x line → substitute.
   - The problem: the range check and finding the regression line do not depend on each other. "Find line, then check x₀ is in range, then substitute" is just as valid, and so is checking x₀ last. A student giving a correct order is marked wrong.
   - Fix (either one):
     - Make the steps genuinely sequential, for example: (1) enter data in L1/L2; (2) find r and check it is close to ±1; (3) run LinReg to get y = ax + b; (4) substitute x₀.
     - Or turn it into a multi-select question: "which checks are needed for a reliable estimate".

4. **q015(b) asks for the "smallest" upper-outlier time, which does not exist for a continuous variable.**
   - Where: `data/questions-t4-1.js:315` and `:323` (q015).
   - Stem: "state the smallest commuting time that would be classified as an upper outlier".
   - Markscheme: "any value strictly above 72 minutes (or 73 minutes if rounded to nearest integer minute)".
   - The problem: commuting time t is continuous, so the set {t > 72} has no smallest element. 72, 73 and "t > 72" are all defensible answers, and the markscheme itself hedges.
   - Fix: change the stem to "state the range of commuting times that would be classified as upper outliers". Answer: t > 72 minutes.

5. **The page says Q₁ and Q₃ are simply multiplied by a and shifted by b. That is wrong when a < 0, because the quartiles swap.**
   - Where: `topics/t4-1.html:230-231` (also `:87`).
   - Line 230: "Measures of position (mean, median, mode, Q_1, Q_3) are multiplied by a and shifted by +b".
   - The problem: for a < 0 the order reverses, so Q₁(y) = a·Q₃(x) + b and Q₃(y) = a·Q₁(x) + b. The worked example on the same page uses a = −3, so a student may apply the rule to quartiles with a negative a.
   - Fix: add "(if a < 0 the order reverses: the new Q₁ is aQ₃ + b and the new Q₃ is aQ₁ + b)".

### Critical

1. **q010's final step shows the wrong value: 0.0799 instead of 0.0803.**
   - Where: `data/questions-t4-2.js:212` (q010, option 4).
   - Text: "Evaluate `1 - binomcdf(10, 0.10565, 2)` and round the final probability to 3 significant figures (<span class="chem">0.0799</span>)".
   - The computation: p = P(M > 175) for N(160, 12²) is 0.105650. Then 1 − binomcdf(10, 0.10565, 2) = 0.080252, which is 0.0803 to 3 s.f.
   - 0.0799 is what you get from a lower p of about 0.1053. A student who checks this on a GDC will get a different number from the one presented as correct.
   - Fix: replace `(<span class="chem">0.0799</span>)` with `(<span class="chem">0.0803</span>)`.
