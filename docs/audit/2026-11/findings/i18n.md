## 2. Cross-language findings (English source or rendering; affects all three overlays)

### Critical

**X-1. `t2-2-q011` answer key is wrong, and the translated solutions contradict it.**
- **Where:** `data/questions-t2-2.js:233-249`. Overlays: `i18n/zh-Hant/t2-2.q.js:245,248`, `i18n/ja/t2-2.q.js:245,248`, `i18n/ko/t2-2.q.js:245,248`.
- **The question:** "Using a GDC, find the solution to `ln(x + 2) = 4 - x` … to 3 s.f."
- **Answer key:** `answer: 2.79, tolerance: 0.015`.
- **True root:** x = 2.4967, i.e. **2.50**.
- **English draft text:** the hint and solution still contain "Wait: let us check the exact intersection! … Let us use 2.50!" and "Wait: let us update answer to 2.50 right now!".
- **Translations:** all three cleaned this up into solutions that state **2.50**:
  - zh: 使用 GDC 求交點得 x ≈ 2.50
  - ja: 答えは 2.50
  - ko: 2.50이에요
- **Effect:** a student in any language who enters the correct 2.50 is marked wrong (|2.50 − 2.79| > 0.015), and then sees a solution saying 2.50.
- **Fix:** in the bank, set `answer: 2.50`. Replace hint[1] with a clean check at x = 2.50, and the solution with e.g. `<p>The intersection of Y₁ = ln(x + 2) and Y₂ = 4 − x is at x = 2.4967… ≈ 2.50 (3 s.f.).</p>`. Then re-run `i18n-extract` / `i18n-check`: the overlay entries for hint[1] and the solution become stale and should be re-translated from the clean English.

### Major

**X-2. README / TRANSLATING.md claim is only partly true for markschemes.**
- **The claim:** README.md:21 says "official IB exam terms and markschemes stay visible in English alongside translations". TRANSLATING.md §2.3 says "Exam Tips, Model Answers, and Markscheme Points (M1, A1, R1): shown automatically in both languages".
- **What I checked:** I rendered topics t2-2, t4-2 and t5-3 in each language with Playwright, plus a code review of `assets/js/core.js:450-453` and `assets/js/quiz.js:33-36`.
- **Holds:**
  - `callout--exam` shows the English, then the translation (`.i18n-tr`): 9/9 pages checked.
  - Every `<dfn>` keeps `<span class="en-term">`: 21/21 on the pages checked, and the tool lints this everywhere.
  - Command terms in stems keep the English in brackets. All 16 "Hence" stems per language have the English and the glossary phrase (由此 / これを用いて / 이를 이용하여).
  - Quiz `markscheme[]` points and short-answer `answer` model answers are rendered bilingually by `bilingual()`.
  - M1/A1/R1/AG codes are never translated.
- **Does not hold:**
  - **Worked examples on topic pages**, the step-by-step markscheme walkthroughs with `[M1 A1]` tags, are shown **only in the translation**. The rendered pages had 0 `.i18n-tr` nodes inside `.worked`.
  - The same is true of question `solution` and `hints`.
  - No page uses `data-i18n="both"`.
- **Effect:** students reading in zh/ja/ko never see the English markscheme-style wording of worked steps, which is exactly what the README promises.
- **Fix:** either add `data-i18n="both"` to `.worked__steps` (or to `.worked__math` and `.worked__answer`) in the topic HTML, or treat `.worked` like `.callout--exam` in `applyLang`. Otherwise, narrow the README sentence to "exam tips, key terms, command terms and question markscheme points".

### Minor

**ZH-1. "vertical (asymptote / line)" rendered 鉛垂 (93 occurrences) against the glossary's 垂直漸近線.**
- **Where:** for example `i18n/zh-Hant/t2-2.q.js:254` (鉛垂漸近線), `t2-2.js:249`, and `t5-2.q.js:178` (鉛垂線 x = 0). Only 1 entry uses 垂直漸近線.
- **Glossary:** §4 says "Vertical asymptote = 垂直漸近線".
- **Fix:** replace 鉛垂漸近線 → 垂直漸近線, and 鉛垂線 → 垂直線 or 直線, across the zh overlays. It is understood, but it is not the listed term.

**ZH-2. Concavity terms are inconsistent.**

- t5-4 uses the glossary's 凹向上 / 凹向下 (7 occurrences).
- **Fix:** use 凹向上 / 凹向下 throughout.

**ZH-3. Mark labels are mixed.** `t5-3.q.js` and `t5-4.q.js` write `[3 分]` (4 stems, e.g. t5-3-q014, t5-3-q017, t5-4-q014). Every other bank keeps `[n marks]` (112 occurrences). Pick one; `[n marks]` matches the "keep IB exam wording" policy.

**ZH-4. Character forms are not consistent HK forms.**
- 恆等 (4 occurrences: `ui.js` ×3, `home.js` ×1) against 恒等 (40 occurrences, matching the glossary 恒等式). Example: `ui.js:70` "畢氏與二倍角恆等式".
- 著 in 接著 / 意味著 (`t1-4.q.js:267`, `t2-1.js:321`, `t2-1.q.js:427`, `t2-2.q.js:273`) where the style guide asks for 着.
- 1 occurrence of 裡, 1 of 資料 and 1 of 常態.
- No Cantonese colloquialisms found.

**ZH-5. "turning points" rendered 極值點 in `t2-1.js:33`; the glossary has 轉向點.** Elsewhere 轉向點 is used, e.g. t5-1-q008.

### Minor

**JA-1. `i18n/ja/t5-1.q.js:264` (t5-1-q012.stem) drops "exact".**
- **EN:** "Find the exact maximum value of f(x) (give your answer to 3 s.f. or in terms of e as a decimal)."
- **ja:** "f(x) の最大値を求めなさい (Find)（有効数字 3 桁、または e の小数表示で答えなさい）"
- **Problem:** "exact" (厳密値) is lost, and "e の小数表示" is unclear. The English itself is self-contradictory.
- **Fix:** first fix the English, e.g. "Find the maximum value of f(x), giving your answer exactly in terms of e or to 3 s.f.". Then use 「f(x) の最大値を求めなさい (Find)。厳密値（e を用いた式）または有効数字 3 桁で答えなさい。」

**JA-2. "exact value" is rendered 正確な値 in UI and stems** (e.g. `ui.js:12`, `t3-2.q.js:12`) rather than the glossary's primary term 厳密値. The glossary lists 正確な値 only in brackets, so this is acceptable. For consistency with "exact value" in IB terms, prefer 厳密値 in stems.
