## Cross-cutting (affects both topics)

### Major

**X1. Many math tokens inside `.chem` spans are shown as raw text, not symbols.** `assets/js/math.js:100–112` (`formula()`) only converts `pi` (and only when it stands alone as a word), `<=>`, `=>`, `->`, `>=`, `<=`, `!=` and `+-`. docs/AUTHORING.md:202 says `theta`, `alpha`, `lambda`, `sqrt(x)` and so on are converted, but the code does not do this. Node output:
- `z \in \mathbb{C}` → shown as `z \in \mathbb{C}` (raw LaTeX). This occurs about 6× in t1-4.html, 24× in t1-5.html, 3× in questions-t1-4.js and 28× in questions-t1-5.js. In t1-5 it appears in nearly every stem (`n \in \mathbb{Z}^+`).
- `theta = 3pi/4` → `theta = 3pi/4`. The `\bpi\b` match fails after a digit, so `2pi`, `3pi/4`, `5pi/6` and `2pi/3` stay as text. This occurs 48× in questions-t1-4.js; `theta` alone appears 54× in t1-4.html and 32× in the t1-4 bank.
- `omega` (20×), `alpha` (7×), `lambda` (16×) and `sqrt(…)` (about 49×) are left as words.
- `90^\circ` (t1-4.html:243, q010 solution) and `arg(z) \in (-\pi, \pi]` (t1-4.html:185 heading) are shown raw.
- `z^*` (t1-4.html:126, q002, q011 and others) stays as `z^*`, because the superscript regex only accepts digits and letters.
- `==` (t1-5.html:60, 98; q001 solution; q003 stem) stays as `==` instead of `≡`.
- `4 \nmid 2` sits in the **correct option** of t1-5 q016 (questions-t1-5.js:357) and is shown raw.

Fix: either extend `formula()` to map `theta α omega lambda sqrt( \in \mathbb{X} \pi \circ \nmid == ^*` and `(\d)pi`, or rewrite the spans with Unicode (θ, ∈ ℝ, √3, ≡, ∤, z*). The root cause is in math.js, which is outside this scope, but the effect shows on both pages.

### Minor

**X2. Widget readouts show caret-brace text.** Readouts are inserted as text, so they display literally, e.g. `2.00 e^{i(π/6)}` (widgets-t1-4.js:87–89, 190), `r^{1/n}` (t1-4:149, 188), `Σ_{r=1}^{3} r²` (widgets-t1-5.js:56, 64) and `5^{2(3)} − 1` (widgets-t1-5.js:69–70). ## t1-4 Complex numbers

### Critical
None. All page answers and all 18 bank answers are correct.

### Major

**4-M1. The roots-polygon widget shows wrong exact angle labels for many slider settings.** `assets/js/widgets-t1-4.js:175, 181, 190` (with `fmtAnglePi`, lines 34–44).
- `var angDeg = Math.round((deg + 360 * k) / n);` rounds the angle to a whole degree before turning it into a fraction of π.
- `fmtAnglePi(deg / n)` is called with a non-integer degree value, but `gcd(Math.round(...),180)` assumes an integer.

Results from node:
- n = 7, θ = 0: labels read `17π/60, 103π/180, 77π/90 …`. The true values are 2π/7, 4π/7, 6π/7, …
- n = 2, θ = 15°: z₀ is labelled `2π/45` (8°). The true value is π/24 (7.5°).
- n = 4, θ = 15°: z₀ is labelled `π/45`. The true value is π/48.
- n = 8, θ = 15°: z₀ is labelled `π/90`. The true value is π/96.

The plotted points are correct; only the exact-form labels are wrong. The defaults and the three presets are fine. Fix: build the label from the exact fraction (θ_deg + 360k)/(180n) as a reduced rational times π, e.g. `num = deg + 360*k; den = 180*n; g = gcd(num, den)`. Do not round the degree value.

### Minor

**4-m1. The worked example's part (b) has more mark tags than marks.** `topics/t1-4.html:254` says `[4 marks]`, but steps 2–3 (lines 264, 265, 269, 270) award M1, A1, M1 A1, A1 = **5** marks. Change it to `[5 marks]`, or merge/drop one tag (e.g. make line 270's sin result part of the same A1).

**4-m2. De Moivre's theorem is stated as a single-valued equality for rational n.** `topics/t1-4.html:294`: "Repeatedly multiplying … This result holds for all rational exponents n ∈ Q", and the dfn says "For any complex number r(cos θ + i sin θ) and rational number n, [r(cos θ + i sin θ)]ⁿ = rⁿ(cos nθ + i sin nθ)".
- The repeated-multiplication argument only proves the result for n ∈ ℤ⁺.
- For non-integer n the left side is multi-valued. For example, −1 = cis π = cis(−π), and n = ½ gives i or −i.

Suggested text: "Proved by induction for n ∈ ℤ⁺ (and true for all n ∈ ℤ). For rational n = p/q, the formula gives one of the q values of z^{p/q}; the others come from replacing θ by θ + 2πk (see n-th roots below)."

**4-m3. The quadrant rule does not cover points on the axes.** `topics/t1-4.html:186`: "First find the acute reference angle alpha = arctan(|b / a|) in (0, pi/2)". This is undefined for a = 0, and the table (lines 200–223) has no row for real or purely imaginary z, e.g. arg(−3) = π, arg(2i) = π/2, arg(−2i) = −π/2. Add a row: "On an axis: arg = 0, π/2, π, −π/2 for positive real, positive imaginary, negative real, negative imaginary."

**4-m4. Two questions have the wrong syllabus reference.** `data/questions-t1-4.js:173` (q008) and `:305` (q014) say `syllabus: 'AHL 1.12'`. Both are conjugate roots of real polynomials, which is **AHL 1.14** in the 2019 AA guide ("Complex conjugate roots of quadratic and polynomial equations with real coefficients"). The page itself correctly puts the theorem under AHL 1.14 (t1-4.html:291, 322). Change both to `'AHL 1.14'`. Note that docs/research/syllabus-topics-1-2.md:192 also wrongly lists the theorem under 1.12.

**4-m5. The label z₁ is used for two different numbers in one worked example.** `topics/t1-4.html:348` vs `:337`. Part (a) names the k = 1 cube root `z_1 = 2e^{i11π/12}` (and uses `z_{−1}`), while part (b) of the same example uses `z_1 = 2 − i`. Rename the cube roots w₀, w₁, w₋₁ (or z_A, z_B, z_C).

## t1-5 Proof and linear systems

### Critical
None. All page answers and all 18 bank answers are correct; every system was solved and matches.

### Major
None, apart from the cross-cutting X1, which hits t1-5 hardest (raw `\in \mathbb{Z}^+` in almost every stem, and `\nmid` in the correct answer of q016).

### Minor

**5-m1. The divisibility example equation is impossible.** `topics/t1-5.html:179`: "isolate the highest exponential term (e.g. 7^k = 6A - 1 or 5^{2k} = 24A + 1)". Since 7^k ≡ 1 (mod 6), 7^k = 6A − 1 has no integer solution. The standard example is 7ⁿ − 1 divisible by 6, which gives 7^k = 6A + 1. Change to `7^k = 6A + 1`.

**5-m2. The systems worked example splits marks wrongly between parts.** `topics/t1-5.html:351–352`. Part (a) says `[5 marks]`, but its tags (lines 357, 358, 362, 363) are M1 A1, A1, M1 A1, A1 = **6**. Part (b) says `[3 marks]`, but its tags (lines 367–368) are M1, A1 = **2**. The total (8) matches. Change to (a) [6 marks], (b) [2 marks], or add an A1 to (b), e.g. for the full vector form, and remove one from (a).

**5-m3. The q017 markscheme has fewer points than the marks.** `data/questions-t1-5.js:382–383` says `marks: 7` and the stem says "[7 marks]", but the markscheme (lines 386–391) has 6 points (R1 M1 M1 A1 A1 R1). Add the missing mark, e.g. "A1: correctly writes the (k+1)-th term (k + 1)·2^k", or change it to 6 marks.

**5-m4. The q004 solution misdescribes the mistake it warns about.** `data/questions-t1-5.js:103`: "Using 2n + 1 for all three numbers only proves the special case where the integers are consecutive!" Using the same 2n + 1 for both odd numbers proves the case where they are **equal**, not consecutive. Also, the even integer cannot be 2n + 1. Suggested: "Using the same letter n for all three numbers (e.g. 2n + 1, 2n + 1, 2n) only proves a special case in which the numbers are related; use independent letters a, b, c."

**5-m5. The AHL rows in the decoder table have no `data-level="ahl"`.** `topics/t1-5.html:69, 74, 79, 84`. The induction, contradiction, counterexample and 3×3-system rows are AHL 1.15/1.16. The CSS rule `:root[data-show="sl"] [data-level="ahl"]{display:none}` (site.css:538) would hide them in "SL core only" mode, but they are not marked, so SL-only users still see them. The visible "(AHL 1.15)" text labels are correct. Add `data-level="ahl"` to those four `<tr>` elements.

**5-m6. The scope callout says "must" for Gaussian elimination.** `topics/t1-5.html:333`: "you must use Gaussian elimination to g(k)z = h(k) to distinguish between no solution and infinitely many solutions." The 2019 AA guide (1.16) expects solving "using both algebraic and technological methods, e.g. row reduction", and any valid elimination or substitution earns credit. What matters is checking consistency once g(k) = 0, not one prescribed method. Suggested: "…use elimination (row reduction) to reach g(k)z = h(k); a zero coefficient alone (e.g. det = 0) cannot tell no solution from infinitely many solutions."

**5-m7. The widget's k-values refer to a system it does not show.** `assets/js/widgets-t1-5.js:196–198, 214–215, 232`. The options "Unique solution (k = 1)", "(k = 3)" and "(k = −3)", and readouts such as "(x, y, z) = (5/4, 1/2, 1/4)", belong to the worked example that appears *after* the widget (t1-5.html:348–350). The widget never states that system, and the planes it draws are generic, not that system's planes. The readouts are correct for that system (checked with sympy). Add a line such as "Using the worked-example system x + y + z = 2, 2x + 3y + 4z = 5, 3x + 4y + (k² − 4)z = k + 4", and note that the diagram is schematic.
