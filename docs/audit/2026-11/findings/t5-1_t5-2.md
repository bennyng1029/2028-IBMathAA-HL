## t5-1

### Critical
None.

### Major

**M1. The f/f'/f'' widget labels non-stationary points as a local maximum or minimum** (`assets/js/widgets-t5-1.js:232-243`)
```js
var eps = 0.04;
...
if (Math.abs(v1) < eps) {
  return v2 < 0 ? t('Local maximum (f\' = 0, f\'\' < 0)') : t('Local minimum (f\' = 0, f\'\' > 0)');
```
The tolerance |f'| < 0.04 is too loose when f' is flat near a root. I ran the classifier on every slider position (step 0.05):
- In the **"Stationary inflexion" model** f(x) = ¼x⁴ − x³ + 2, f'(x) = x³ − 3x²:
  - x₀ = 0.05 and x₀ = 0.10 show **"Local maximum (f' = 0, f'' < 0)"**. Here f'(0.1) = −0.029 and f''(0.1) = −0.57.
  - x₀ = −0.05 and x₀ = −0.10 show **"Local minimum (f' = 0, f'' > 0)"**.
  - This function has **no local maximum at all**, and its point at x = 0 is the stationary inflexion that the model exists to teach. A student scanning through 0 sees "min → stationary inflexion → max", which is exactly the misconception the page warns against.
- In the **"Quartic trap" model** ¼x⁴ − 1, every x₀ from −0.30 to 0.30 is labelled a local minimum. The f' readout also shows "0.03 (0)" at x₀ = 0.3.

Suggested fix: only report a stationary point when f' changes sign within one slider step, or use a much tighter tolerance tied to the step, e.g. `Math.abs(v1) < 1e-3`. Better still, snap to the model's known critical x-values. Otherwise fall through to the "Increasing/Decreasing, concave …" text. The same sign-change test is already used for f''.

- `t5-1-q009` (line 201): "Points of inflexion with zero and non-zero gradients" is listed under SL 5.8 → `'SL 5.7, 5.8'`.

### Minor

**m1. The f/f'/f'' table states a sufficient condition as if it were necessary** (`topics/t5-1.html:270` and `:275`)
The "Local maximum of f(x)" row says `f''(x) < 0 (below the x-axis)`, and the "Local minimum" row says `f''(x) > 0`. A few lines earlier (line 242) the page itself shows that x⁴ has a minimum with f''(0) = 0. Suggested text: "f''(x) ≤ 0 at that point (usually < 0; f'' = 0 is possible, e.g. y = −x⁴)", and the matching text for the minimum row.

**m2. Awkward wording** (`topics/t5-1.html:237`)
"…or **non-stationary** (f'(a) != 0, where the gradient reaches a steepest local extremum)." "Steepest local extremum" does not make sense. Suggested: "(f'(a) ≠ 0; here the gradient f'(x) itself has a local maximum or minimum)".

**m3. The question stem contradicts itself** (`data/questions-t5-1.js:262`, q012)
"Find the **exact** maximum value of f(x) (give your answer to 3 s.f. or in terms of e as a decimal)." "Exact" and "to 3 s.f." conflict, and "in terms of e as a decimal" makes no sense. Suggested: "Find the maximum value of f(x). Give your answer correct to 3 significant figures (the exact value is in terms of e)."

**m4. Mark tags do not add up to the stated marks**
- `data/questions-t5-1.js:347-356` (q016): part (b) is marked **[6 marks]**, but its markscheme lines award only M1 A1, M1, A1, A1, which is 5 marks. There is also no mark for justifying the minimum. The solution does mention "T'(x) changing from − to +". Add an "R1: T'(x) changes sign from − to + (or T(45) = 36 < T(0) = 40, T(100) ≈ 38.9), so minimum" line. Part (a), worth [2 marks], shows only M1 + AG. Add an A1 for the two distances, or make it [1 mark].
- `topics/t5-1.html:364-371` (box worked example): part (a) is marked **[2 marks]** but shows only [M1] and [AG]. Add [A1] to the line `A = x² + 4xh` (correct expression for the area), or change it to [1 mark].

### Major

**M3. Wrong formula-booklet/syllabus section labels** (`topics/t5-2.html:95`, `data/questions-t5-2.js`)
- `topics/t5-2.html:95`: "In your formula booklet (SL 5.5): Standard integrals…" lists ∫1/x, ∫sin x, ∫cos x and ∫eˣ. In the 2019 guide and booklet these are under **SL 5.10**. SL 5.5 only has ∫xⁿ (n ∈ ℤ, n ≠ −1). Suggested: "In your formula booklet (SL 5.5 & 5.10):".
- `t5-2-q001` (line 16) is tagged `'SL 5.5'`, but it integrates e^{2x} and cos(3x), which are SL 5.10 → `'SL 5.10'`.
- `t5-2-q004` (line 87) is tagged `'SL 5.5'`, but it asks for an analytic definite integral of an exponential on Paper 1. SL 5.5 is "definite integrals **using technology**" → `'SL 5.10, 5.11'`.
- `t5-2-q005` (line 104) is tagged `'SL 5.5'`. Properties of definite integrals, done analytically, belong to SL 5.11 → `'SL 5.11'`.
- `t5-2-q015` (line 314) is tagged `'SL 5.5, 5.10'`. It uses linearity, a shift and the constant term → `'SL 5.10, 5.11'`.

### Minor

**m5. Wrong turning time in the solution note** (`data/questions-t5-2.js:241`, q011)
"(Note: … because v(t) turns negative around **t ≈ 2.74** s.)" Solving 4 sin t − t + 1 = 0 numerically gives t = 2.702; at t = 2.74, v = −0.18. The answer key (10.7) is unaffected. Change to "t ≈ 2.70 s".

**m6. The horizontal-shift property's explanation contradicts its formula** (`topics/t5-2.html:192`)
"`int_a^b f(x - k) dx = int_{a-k}^{b-k} f(u) du` (shifting the curve right by k shifts the limits right by k)." The formula shows the limits moving **left** (a − k, b − k). The bracket describes the other way of reading it, which will confuse students. Suggested: "(the curve y = f(x − k) is y = f(x) shifted right by k, so the area under it on [a, b] equals the area under f on [a − k, b − k])".

**m7. Garbled area-splitting instruction** (`topics/t5-2.html:71`)
"Find any x-intercept c in (a, b) where f(x) < 0 and split: ∫_a^c f(x) dx − ∫_c^b f(x) dx." The intercept is not "where f(x) < 0", and the formula only holds if f ≥ 0 on [a, c] and f ≤ 0 on [c, b]. Suggested: "Find every x-intercept c in (a, b), split the integral there, and take the absolute value of each piece, e.g. ∫_a^c f(x) dx − ∫_c^b f(x) dx when f ≥ 0 on [a, c] and f ≤ 0 on [c, b]."

**m8. Missing condition** (`topics/t5-2.html:60`)
"`int g'(x) [g(x)]^n dx = [g(x)]^{n+1} / (n + 1) + C`" has no "(n ≠ −1)". The same page states this condition everywhere else (lines 36, 97, 107). Add "(n ≠ −1)".

**m9. Misconception note does not make sense** (`data/questions-t5-2.js:72`, q003 distractor 8 ln(2x²+3))
"The derivative of the denominator 2x² + 3 is 4x, **not x**, so 8x = 2(4x)…" Nobody gets "x" here. The 8 ln error comes from treating 8x as if it were already g'(x). Suggested: "The derivative of the denominator 2x² + 3 is 4x, not 8x, so 8x = 2(4x) gives 2 ln(2x² + 3), not 8 ln(2x² + 3)."

**m10. Obsolete, non-standard markup** (`topics/t5-2.html:228-229`)
The worked area example uses `<Big>[</Big>`, `<Big>(</Big>`, etc. `<big>` is obsolete in HTML5, and it appears nowhere else on the site (`grep` finds it only in t5-2.html). It renders, but it is inconsistent and may fail HTML validation. Replace it with plain brackets or the site's existing math-bracket styling.
